# teslam.io — Genesis 500을 작동시키는 설계

- 날짜: 2026-08-13
- 단계: 백서 Table 8의 **0단계 (Genesis 500 사전 등록)**, 게이트 = 500석 확정
- 출처: `teslam-whitepaper-v0.1-draft.pdf` (내부 검토용 초안, 공개 문서 아님)
- 참조 구현: `satellite.agentba.se` (Vercel + Cloudflare Worker + D1)

---

## 1. 무엇을 만드는가

지금 teslam.io는 화면은 완성돼 있고 **작동하는 것이 하나도 없습니다.** Genesis 500
신청 버튼은 `https://forms.gle/` — 빈 껍데기라 어디에도 도달하지 않고, 좌석
카운터 `347/500`도 접속자 `1284`도 지어낸 숫자입니다.

목표는 하나입니다: **Genesis 500 등록을 진짜로 만들고, 그것이 만들어내는 진짜
데이터로 화면을 채운다.**

핵심 통찰은 등록이 진짜가 되면 **지역 밀도 지도가 자동으로 진짜가 된다**는 것입니다.
지금까지 라이브 맵은 가짜 차량을 찍는 구상이었지만, 등록자 분포를 그리면 실제
데이터입니다. 그리고 백서 §10.1이 이 사업의 성패 조건으로 지목한 것이 정확히
**밀도**입니다. 사이트에서 유일하게 진짜인 지표가 사업이 증명해야 하는 바로 그
지표가 됩니다.

판정 기준은 기능이 아니라 **테슬람이 다시 오고 싶은가**입니다. 등록 후 아무 감흥이
없으면 이 작업은 실패입니다.

## 2. 명시적 비범위

각각 왜 아닌지가 중요합니다.

| 제외 | 이유 |
| --- | --- |
| DRV 적립 엔진 | Tesla Fleet Telemetry 사업자 계정 + 개발자 앱 승인 + 오너별 OAuth가 전제. 백서 1단계 |
| 검증기 V1–V4 | 적립할 데이터가 없으면 검증할 것도 없음. 1단계 |
| TSLM·전환·시즌 | 백서 §11.3 관할 법제 확정 전. 발행된 바 없음 |
| 게시판 쓰기·로그인 | 회원 0명. 500석이 차기 전에는 쓸 사람이 없음 |
| 퀘스트·티어 | 백서 2단계. 지금 넣으면 작동하지 않는 UI를 진짜처럼 보이게 하는 것 |
| VIN 수집 | VIN↔계정 결속은 Tesla OAuth로만 (백서 §3.3). 사전등록에서 받으면 검증 불가능한 자기신고 |

**위치 정보는 어느 단계에서도 수집하지 않습니다.** 사전등록의 "지역"은 사용자가
직접 고르는 광역 구분이며 개인위치정보가 아닙니다. 위치기반서비스사업자 신고는
1단계(텔레메트리) 진입 조건이지 이번 범위의 전제가 아닙니다.

### Go는 왜 지금이 아닌가

한 차례 "Go 백엔드"로 정했다가 되돌린 결정입니다. Cloudflare Worker는 JS/TS
런타임이고, 실시간 계층(Durable Object + WebSocket)이 이번 작업의 핵심 요구입니다.
지금 Go를 넣으면 배포 대상이 셋이 되고 저장소가 둘로 갈리는데, 그 복잡도가 사는
것은 "Go를 썼다"는 사실뿐입니다.

Go는 **백서 1단계에서 제 역할을 합니다** — 텔레메트리 수집기, 검증기 V1–V4,
적립 원장. 장시간 실행·고처리량·수치 연산이라 Worker보다 Go가 맞고, 그때는 전용
서버가 필요해집니다. 그 시점에 들어갑니다.

## 3. 아키텍처

```
브라우저
  │
  ├── Vercel ─ Next.js (App Router)                    teslam.io
  │     · 정적 + ISR. 첫 페인트에 필요한 집계는 서버에서 주입
  │
  └── Cloudflare ─ Worker (TypeScript)                 api.teslam.io
        ├─ D1        registrations (durable store)
        ├─ DO        LiveBoard — WebSocket 팬아웃 · 접속자 수 · 좌석 점등
        └─ Cron      집계 스냅샷 재계산 (5분)
```

satellite과 같은 분리입니다: 프론트는 Vercel, 데이터·실시간은 Cloudflare 커스텀
도메인. CORS는 `ALLOWED_ORIGINS` 허용목록으로 좁히고, 프로덕션은
`workers_dev: false`.

**환경은 preview/production 둘.** satellite처럼 D1도 `teslam-preview` /
`teslam-production`으로 분리해, 프리뷰에서 만든 등록이 실제 좌석을 먹지 않게 합니다.

### 정적 유지 원칙의 변경

현재 `lib/site.ts`는 *"사이트는 완전 정적이며 아무것도 수집하지 않는다 — 지킬 DB가
없다"* 를 설계 원칙으로 명시합니다. 이 설계는 **그 원칙을 의도적으로 깹니다.**
주석을 갱신하고 무엇을 대신 지키는지 적습니다: 최소 수집, 위치 없음, VIN 없음,
동의 기록, 보관 기간 명시, 공개 엔드포인트는 집계만.

## 4. 데이터 모델 (D1)

```sql
CREATE TABLE registrations (
  id                TEXT PRIMARY KEY,           -- uuid
  seat_no           INTEGER UNIQUE,             -- 1..500. NULL이면 대기열
  waitlist_no       INTEGER UNIQUE,             -- 501번째부터
  email             TEXT NOT NULL UNIQUE,       -- 소문자 정규화
  verified_at       INTEGER,                    -- 이중 옵트인 완료 (epoch)
  verify_token_hash TEXT,                       -- 원문 저장 안 함. 확인 후 NULL
  model             TEXT NOT NULL,              -- Model 3 | Y | S | X | Cybertruck
  trim              TEXT NOT NULL,
  region            TEXT NOT NULL,              -- 광역 구분. 자기신고, 좌표 아님
  km_band           TEXT NOT NULL,
  consent_terms     INTEGER NOT NULL,
  consent_privacy   INTEGER NOT NULL,
  consent_marketing INTEGER NOT NULL DEFAULT 0,
  consent_at        INTEGER NOT NULL,
  created_at        INTEGER NOT NULL
);
CREATE INDEX idx_reg_region ON registrations(region) WHERE seat_no IS NOT NULL;
CREATE INDEX idx_reg_seat   ON registrations(seat_no);
```

마이그레이션은 `wrangler d1 migrations`.

**설계와 달라진 점 — ORM을 쓰지 않았습니다.** 이 문서는 satellite에 맞춰
drizzle-orm을 지정했지만, 구현해 보니 테이블 하나에 쿼리 여섯 개였습니다. 의존성
하나와 코드젠 단계(그리고 그것이 낡을 가능성)를 더할 만큼의 값이 나오지 않아 D1
prepared statement를 직접 씁니다. 조인이 생기면 그때 다시 봅니다.

좌석 배정도 문서의 서술과 달라졌습니다. "읽고 나서 쓴다"로 구현했더니 동시
확인 12건에서 재시도가 O(n)으로 터졌습니다. 지금은 **한 UPDATE 문 안에서 SQLite가
직접 최소 미사용 번호를 고르고 `RETURNING`으로 돌려줍니다** — 읽기와 쓰기 사이의
간격 자체가 없어져 재시도가 필요 없습니다.

### 정규 어휘 — 지금 어긋나 있음

현재 샘플 데이터가 자기모순입니다. `data/community.json`의 `regions`는 4개
(`수도권`·`부·울·경`·`대전·충청`·`제주`)인데 `leaderboard`는 목록에 없는
`영남`·`충청`을 씁니다. 밀도 지도를 그리려면 어휘가 하나여야 하므로 여기서
고정합니다.

| `region` | 표기 | 포함 |
| --- | --- | --- |
| `capital` | 수도권 | 서울·경기·인천 |
| `gangwon` | 강원 | 강원 |
| `chungcheong` | 대전·충청 | 대전·세종·충북·충남 |
| `daegu` | 대구·경북 | 대구·경북 |
| `busan` | 부산·울산·경남 | 부산·울산·경남 |
| `jeolla` | 광주·전라 | 광주·전북·전남 |
| `jeju` | 제주 | 제주 |

기존 4구분은 수도권이 지도를 삼켜 밀도 차이가 안 보입니다. 7구분이 백서 §10.1의
"생활권" 단위에 더 가깝고, TopoJSON 시도 경계와도 맞습니다.

```
model    Model 3 | Model Y | Model S | Model X | Cybertruck
km_band  under_500 | 500_1000 | 1000_2000 | over_2000   (월 km)
```

`trim`은 자유 입력이 아니라 선택 목록으로 두고, 모델별 목록은 `data/trims.json`에
둡니다 — 샘플 리더보드가 이미 `Model 3 하이랜드` 같은 값을 쓰고 있으므로 그
어휘를 정리해 재사용합니다.

**좌석 번호는 이메일 확인 시점에 배정합니다.** 신청 시점이 아니라. 확인하지 않은
신청이 좌석을 점유하면 카운터가 거짓이 되고, 이 사이트에서 카운터는 유일한 진짜
숫자입니다.

수집하지 않는 것: 전화번호, 주소, VIN, 좌표, 생년월일. IP는 레이트리밋 키로만
쓰고 저장하지 않습니다.

보관: 1단계 초대 발송 시점까지, 초대 후 6개월 미응답이면 파기. 방침에 명시.

## 5. API (Worker)

| 메서드 | 경로 | 용도 |
| --- | --- | --- |
| `POST` | `/v1/genesis/register` | 신청 접수 → 확인 메일 발송 |
| `GET` | `/v1/genesis/confirm?token=` | 확인 → 좌석 배정 → 프론트로 리다이렉트 |
| `GET` | `/v1/genesis/stats` | 공개 집계 (첫 페인트용) |
| `WS` | `/v1/live` | LiveBoard 구독 |
| `GET` | `/v1/genesis/export` | 운영자 전용 (Bearer). CSV |

`stats` 응답 — 집계만. 개인 단위 필드는 어떤 공개 경로에도 없습니다.

```json
{
  "seats": 500, "taken": 0, "waitlist": 0, "watching": 0,
  "byRegion": [{ "region": "capital", "count": 0 }],
  "recent": [{ "seatNo": 1, "region": "capital", "model": "Model 3", "at": "..." }],
  "updatedAt": "2026-08-13T00:00:00Z"
}
```

`recent`는 익명입니다 — 좌석번호·지역·모델만. 이름도 이메일도 없습니다.

레이트리밋: IP당 시간당 5회 등록 시도. 초과 시 429.

## 6. 실시간 — LiveBoard Durable Object

단일 DO가 모든 관전자를 붙듭니다. **WebSocket Hibernation API**를 쓰므로 유휴
상태에서 과금 대상 시간이 거의 없습니다.

- `seat.taken` — 좌석 확정 시 브로드캐스트: `{seatNo, region, model}`
- `watching` — 연결·해제 시 현재 관전자 수 브로드캐스트
- 스냅샷 — 신규 접속자에게 현재 상태 1회 전송 후 증분만

**가짜 `onlineNow: 1284`를 실제 연결 수로 교체합니다.** 지금 이 화면을 같이 보고
있는 사람 수는 지어낼 필요가 없는, 그 자체로 진짜인 숫자입니다.

폴백: WebSocket 실패 시 `stats`를 10초 폴링. 기능이 사라지지 않고 즉시성만 떨어집니다.

## 7. 화면 — alt에서 무엇을 가져오는가

alt 10안 중 **3안만** 흡수합니다. 나머지는 지금 넣으면 작동하지 않는 화면이 됩니다.

### 7.1 ALT3 라이브 맵 → 등록 밀도 지도

티커의 가짜 수치를 대체합니다. 광역 구분에 등록자 수를 얹은 한국 지도.
`d3-geo` + `topojson-client`로 그립니다 (satellite과 동일 스택, 외부 타일 요청 없음).

라벨은 *"지금 달리는 차"* 가 아니라 **"등록 밀도"** 입니다 — 있지도 않은 주행을
암시하지 않습니다.

이게 매력의 축입니다. 예비 참여자가 보는 것은 총계가 아니라 **"우리 동네에 몇 명"**
이고, 백서 §10.1의 *"리그는 아는 얼굴이 있어야 돌고, 상환처는 생활권에 있어야
쓴다"* 가 화면에서 바로 읽힙니다.

**인터랙션**: 지역 호버·탭 → 해당 지역 좌석만 발광 + 그 지역 최근 등록 표시.
새 등록 이벤트 → 해당 지역에서 파문이 번지고 좌석 하나가 점등.

### 7.2 500석 그리드 → 차오르는 긴장

500칸이 실제 배정 상태로 그려집니다. 빈 칸·찬 칸·방금 찬 칸(점등 애니메이션).
희소 코호트라는 사실 자체가 화면의 동력입니다.

`prefers-reduced-motion`을 존중합니다 — 점등은 상태 변화로만 표시하고 애니메이션은
생략합니다.

### 7.3 ALT7 레트로 계기판 → 좌석 확인 화면

`components/hero/cluster.tsx`가 이미 이식돼 있는데 `/model`에서만 쓰입니다. 이걸
**좌석 배정 순간**에 씁니다: 7세그먼트로 찍힌 내 좌석 번호, 스캔라인, 게이지.

이것이 공유 자산입니다. ALT10(컬트/밈)이 노린 "스크린샷 찍어 퍼뜨리고 싶은 화면"을
ALT10의 맥시멀리즘 없이 ALT7의 화면으로 달성합니다. `/genesis/seat/<no>`에
OG 이미지를 생성하면 공유 시 그 계기판이 그대로 뜹니다.

### 7.4 ALT2 내 차고 → 명패 씨앗

등록 시 받은 모델·트림·지역으로 확인 화면에 명패를 그립니다. 1단계에서 VIN이
결속되면 실제 차고로 자랍니다. 지금은 씨앗만.

### 7.5 샘플과 진짜가 섞이는 문제

현재 `isPreview` 배너는 *"아래의 모든 것이 샘플"* 이라고 말합니다. 좌석수·지도·
관전자 수가 진짜가 되는 순간 **이 문장이 거짓이 됩니다.**

문구를 바꾸고 무엇이 진짜인지 명시합니다:

> 서비스는 시작 전입니다. **등록 좌석수·지역 분포·접속자 수는 실제 수치**이며,
> 게시글·순위·지갑 내역은 화면 구성을 보여주는 샘플입니다.

그리고 테스트를 바꿉니다. `tests/no-slop.test.ts`의 샘플 라벨 검증은 지금
`isPreview` 하나에 걸려 있는데, **진짜 영역과 샘플 영역을 각각 검증**하도록
분리합니다. 섞인 화면에서 라벨이 뭉뚱그려지는 것이 이 작업의 가장 큰 정직성
위험입니다.

## 8. 실사 이미지

CSS·SVG만으로 그려진 현재 화면에 포토리얼 이미지를 넣습니다.

- 히어로 배경 1장, OG 1장, 지역 카드 소재 약간
- **제약**: 실존 인물 없음, 판독 가능한 번호판 없음, Tesla 공식 자산처럼 보이지
  않게. 사이트는 *"Tesla, Inc.와 제휴하거나 후원받는 관계가 아닌 독립 커뮤니티
  프로젝트"* 를 명시하고 있고, 이미지가 그 진술과 모순되면 안 됩니다.
- 형식: AVIF/WebP, `next/image`, 히어로 200KB 이하

## 9. 백서 정합성 — 지금 틀린 숫자

`data/model.json`의 `pricePerSignalUsd`가 `0.0001`인데, 백서 §7.2는
`$1 / 150,000 signals` = `6.67e-06`입니다. **15배 과대**이며, 백서가 이유를 명시합니다
— *"2024년 10월 최초 발표안($0.0001/시그널)의 15배 인하 개정"*. 사이트는 개정 전
가격을 쓰고 있습니다.

결과: `/model`이 API 원가를 월 약 1,000원으로 계산합니다. 백서는 67원입니다.

이 오류는 사이트가 **자기 논지를 약화시키고** 있다는 뜻입니다. 주장은 "API 비용은
반올림 오차, 진짜 비용은 상환"인데 원가를 15배 부풀린 채 그 주장을 합니다. 백서
값으로 고치면 API 비중이 3.2%가 되어 논지가 선명해집니다.

**재발 방지**: 백서 파라미터를 `data/whitepaper-params.json`으로 체크인하고
(출처·버전·절 번호 명기), `data/model.json`이 벗어나면 실패하는 테스트를 둡니다.
백서 개정 시 픽스처 갱신이 명시적 행위가 됩니다.

## 10. 법적 표면

PII를 수집하는 순간 필요한 것들입니다. 지금은 없습니다.

- `/privacy` — 수집 항목, 목적, 보관·파기, 제3자 미제공, 처리위탁(Cloudflare·
  Vercel·메일 발송), 정보주체 권리, 책임자 연락처
- `/terms` — Genesis 500이 사전 등록이며 재화·토큰의 판매나 배분 약속이 아님을 명시
- 약관·개인정보 동의는 **필수 개별 체크**, 마케팅 수신은 선택
- 백서가 내부 문서임을 존중 — 사이트에 공개하거나 링크하지 않습니다
- DRV·TSLM 미발행 진술을 등록 흐름에도 유지. 좌석을 얻는 것이 토큰을 얻는 것이
  아니라는 점이 등록 화면에서 읽혀야 합니다

## 11. 테스트

| 대상 | 방법 |
| --- | --- |
| Worker 핸들러 | `@cloudflare/vitest-pool-workers` (실제 workerd + D1) |
| 좌석 경합 | 동시 확인 요청에서 좌석 번호 중복 없음 |
| 대기열 전환 | 501번째 경계 |
| 미확인 등록 | 좌석을 점유하지 못함 |
| 공개 stats 누출 | 이메일·토큰이 응답에 없음 |
| DO 브로드캐스트 | 연결 2개에서 `seat.taken` 수신, `watching` 증감 |
| 백서 정합성 | `model.json` vs `whitepaper-params.json` |
| 혼합 라벨 | 진짜 영역·샘플 영역이 각각 올바르게 라벨되는지 (SSR HTML) |
| 기존 55개 | 전부 유지. 깨지면 회귀 |

`keel:guardrail-proof`를 적용합니다 — 위치 필드 주입, 미확인 좌석 점유 시도,
stats 개인정보 누출, 레이트리밋 우회를 각각 시도해서 막히는 것을 표로 남깁니다.

## 12. 배포

- **Vercel**: 기존 프로젝트 그대로. 프론트만.
- **Cloudflare**: `cloudflare/wrangler.jsonc`, 커스텀 도메인 `api.teslam.io`,
  D1 preview/production 분리, observability 활성
- 스크립트는 satellite 명명을 따릅니다: `cf:types` · `cf:check`(dry-run) ·
  `cf:migrate:preview|production` · `cf:deploy:preview|production`
- CI에 `cf:check`를 넣어 배포 전에 타입·번들이 검증되게 합니다
- 시크릿은 `wrangler secret` / Vercel 환경변수. 리포에 `.env`를 만들지 않습니다
  (Keel `protect-secrets`가 차단)
- 프로덕션 배포는 사람이 실행

## 13. 순서

1. 백서 정합성 수정 + 픽스처 테스트 — 가장 작고 가장 급함 (틀린 숫자가 공개돼 있음)
2. `/privacy`, `/terms` — 수집 전에 있어야 함
3. Worker + D1 스키마 + 마이그레이션 + 등록·확인 API + 테스트
4. LiveBoard DO + WebSocket + 폴백
5. 등록 폼 → 확인 메일 → 좌석 배정 → 계기판 확인 화면
6. 밀도 지도 + 500석 그리드를 실데이터·실시간에 연결
7. 혼합 라벨 정리 + 테스트 갱신
8. 실사 이미지

1–2를 3 이후에 하면 안 됩니다. 개인정보를 받기 시작한 뒤에 방침을 쓰는 순서는
거꾸로입니다.

## 14. 기본값을 정해둔 결정

구현을 막지 않도록 각각 기본값을 정해둡니다. 바꾸고 싶으면 말씀만 하시면 됩니다.

- **메일 발송** — 이중 옵트인이 필요하므로 발송은 선택이 아닙니다. 기본값은
  **Resend** (Worker에서 `fetch` 한 번으로 끝나고 도메인 인증이 단순). 이미 쓰는
  발송 경로가 있으면 그쪽으로 바꿉니다. 발송 실패는 등록을 실패로 처리하지 않고
  재발송 가능한 상태로 남깁니다.
- **좌석 카운터 시작값** — **진짜 0에서 시작합니다.** 지어낸 347을 유지하거나
  적당한 숫자로 대체하는 것은 이 사이트가 코드로 강제해 온 정직성과 정면으로
  충돌합니다. 0석은 부끄러운 숫자가 아니라 사전등록 첫날의 사실이고, 차오르는
  과정 자체가 §7.2가 노리는 긴장입니다.
- **`onlineNow` 처리** — 실제 WebSocket 연결 수로 교체합니다. 관전자가 1명이면
  1로 표시합니다. 하한을 두어 부풀리지 않습니다.

## 15. 이 문서의 크기에 대해

한 번에 실행하기에 큰 편입니다 — Worker·DO·프론트 재구성·법적 페이지·이미지가
함께 들어 있습니다. §13의 순서가 그대로 분할선입니다. 1–2는 독립적으로 배포
가능하고, 3–4는 화면 없이도 테스트로 검증되며, 5–8이 사용자에게 보이는 부분입니다.

구현 계획은 이 순서를 그대로 단계로 삼아 작성합니다.
